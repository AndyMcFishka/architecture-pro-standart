# RoadMap — состав задач

Назначения команд — предложение для планирования; доступность исполнителей не подтверждена. Сроки и последовательность заданы только в [RoadMap](task4-roadmap.drawio).

| ID | Полное содержание | Ответственный |
| :- | :- | :- |
| A1 | Согласовать минимальные API, формат файла и права; подготовить заглушки | Владельцы процесса / цифровая трансформация |
| A2 | Утвердить правила ставок и идентификации | Владельцы процесса / цифровая трансформация |
| A3 | Правила автоматического открытия | Владельцы процесса / цифровая трансформация |
| I0 | Проверить ЦОД, лицензии, ресурсы и возможность резервирования сайта и колл-центра; согласовать время восстановления | Инфраструктура и сопровождение с разработчиками сайта и подрядчиком колл-центра |
| I1 | Kafka, БД, резервирование и ключи; безопасный переход к локально устойчивой записи при отказе одного ЦОД и возврат к синхронной репликации; балансировка, синхронные реплики и переключение данных сайта и PostgreSQL колл-центра | Инфраструктура и сопровождение |
| I2 | Мониторинг сервисов, доставки и подтверждения импорта; оповещения при отказе и отсутствии ответа | Инфраструктура и сопровождение |
| D1 | Справочник и интерфейс бэк-офиса; API ставок для колл-центра, проверка прав и аудит персонального доступа | Интернет-банк: команда банка |
| D2 | Приём заявок, счета, СМС-код, outbox; последовательное применение статусов и сохранение событий при пропуске | Интернет-банк: команда банка |
| D3 | Полный снимок общих ставок каждые 15 минут; SFTP-доставка, повторы, чтение обязательного результата импорта | Интернет-банк: команда банка |
| D4 | Автоматизировать обработку заявки | Интернет-банк: команда банка |
| D5 | Проверить автоматическое открытие | Интернет-банк: команда банка |
| B1 | API, адаптер и журнал событий | Команда АБС |
| B2 | Обмен счетами, заявками и статусами; дедупликация, номера событий заявки и восстановление пропусков из журнала | Команда АБС |
| B3 | Автоматическое открытие с проверками | Команда АБС |
| B4 | Процесс отделения без бэк-офиса | Команда АБС |
| L1 | Приём обращений сайта и outbox | Интернет-банк: подрядчик, поток обращений |
| L2 | Доставка через Kafka и адаптер в колл-центр | Интернет-банк: подрядчик, поток обращений |
| N1 | Приём заданий Kafka и хранение доставки | Интернет-банк: подрядчик, поток уведомлений |
| N2 | СМС-шлюз, повторы и срок действия кода; последовательная передача двух уведомлений заявки | Интернет-банк: подрядчик, поток уведомлений |
| W1 | Общие ставки и форма обращения | Команда сайта |
| W2 | Подключить API ставок и обращений; обеспечить работу сайта, сессий и внутренних зависимостей в двух ЦОД | Команда сайта |
| W0 | Измерить и оптимизировать загрузку платёжных справочников; проверить отклик меньше секунды без роста нагрузки на АБС | Интернет-банк: команда банка; команда АБС при изменении её запросов |
| W3 | Форма депозита и выбор счёта | Интернет-банк: команда банка |
| W4 | Подключить подачу, СМС-код и статусы | Интернет-банк: команда банка |
| C1 | API приёма обращений с защитой от дублей | Подрядчик колл-центра |
| C2 | HTTPS-просмотр общих и персональных ставок; работа платформы и внутренних зависимостей колл-центра в двух ЦОД | Подрядчик колл-центра |
| P1 | SFTP и проверка формата полного файла | Команда партнёра |
| P2 | Проверка и атомарный импорт реальной выгрузки; обязательный ответный файл; скрытие снимка через 30 минут | Команда партнёра |
| T1 | Сквозные тесты, нагрузка, отказ каждого ЦОД, включая сайт и колл-центр; новые записи в аварийном режиме, блокировка небезопасной записи и восстановление репликации; повторная проверка платёжных справочников по P-01; обучение | Цифровая трансформация + владельцы систем |
| PILOT | Пилот после сквозной приёмки, перед запуском MVP | Цифровая трансформация + владельцы систем |
| T2 | Приёмка автоматизации депозитов и накопительных счетов | Цифровая трансформация + владельцы систем |
| MVP | Запуск MVP после пилота | Цифровая трансформация + владельцы систем |
| AUTO | Запуск без бэк-офиса к концу Q4 | Цифровая трансформация + владельцы систем |

Команда интернет-банка выполняет D1–D5 и W0, W3–W4. План предполагает два параллельных состава для W0/D1 и D3/W3; после W0 его исполнители переходят к W3–W4. Если оптимизация требует изменений запросов АБС, её участие планируется с учётом B1. У подрядчика интернет-банка также нужны два параллельных состава: для L1–L2 и N1–N2. B1–B4 и C1–C2 выполняются последовательно своими командами.

В I0 руководитель проекта с владельцами команд подтверждает эти ресурсы, компетенции подрядчика в .NET и назначает разработчиков сайта, партнёра и инфраструктуры. Объём резервирования сайта и колл-центра учитывается в оценках I1, W2 и C2. Если исполнителей недостаточно, до утверждения плана пересматриваются последовательность и сроки работ. Условия приёмки приведены в [ADR](adr.md#приёмка-mvp).

Разработка MVP идёт блоками по одному–два условных спринта. Пик — шесть задач, а не шесть независимых команд. Оценки длительности предварительные.
