# Требования FURPS+

Д1-Д6 и К1-К6 - пункты депозитного и кредитного направлений задания 2.

| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | Функциональные (Functionality) | |
| F-01 | На сайте доступны депозиты с актуальными ставками и подача заявки по ФИО и телефону | Д1 |
| F-02 | Заявка с сайта поступает в систему колл-центра. Менеджер связывается с клиентом и предлагает условия, в том числе особые | Д1 |
| F-03 | В интернет-банке доступны общие и персональные ставки. Клиент подаёт заявку на депозит, указав счёт и сумму, и подтверждает её СМС-кодом | Д2 |
| F-04 | Депозитный и кредитный бэк-офис ведут ставки в системе. Онлайн-каналы показывают актуальные ставки | Д2. Сейчас ставки хранятся только в XLS |
| F-05 | В MVP бэк-офис обрабатывает депозитную заявку и подтверждает условия в АБС. Клиент получает СМС после подтверждения ставки и открытия депозита | Д4. Два отдельных уведомления |
| F-06 | Сайт и интернет-банк показывают актуальные условия кредитов из Кредитного конвейера | К1, К3 |
| F-07 | Сайт принимает кредитную заявку по ФИО и телефону. При заполнении паспортных данных клиент сразу получает предварительное решение по скорингу | К1, К2. Для нового клиента используются только данные БКИ |
| F-08 | После кредитной заявки на сайте клиент получает СМС с приглашением в отделение для идентификации и получения кредита | К1 |
| F-09 | Менеджер в АБС продолжает заявку с сайта с учётом предварительного решения. Если заявки нет, создаёт новую | К2. Единая заявка между каналами |
| F-10 | Интернет-банк показывает предодобренные кредиты с доступной суммой. После подачи заявки скоринг повторяется по упрощённой процедуре, если ситуация клиента изменилась | К3 |
| F-11 | Клиент подаёт кредитную заявку в интернет-банке, указав данные и счёт зачисления, и подтверждает её СМС-кодом | К3 |
| F-12 | Клиент получает СМС при изменении статуса кредитной заявки | К6 |
| F-13 | Чувствительные данные сайта и интернет-банка передаются по зашифрованным каналам | Д1, Д2 |
| F-14 | Доступ депозитного и кредитного бэк-офиса разграничен. Совместная работа со ставками не открывает доступ к данным другого подразделения | Исходный депозитный процесс, п. 5 |
| F-15 | Изменения ставок и статусов заявок фиксируются: кто, когда и что изменил | Дополнительно. Для разбора ошибок и спорных операций |
| F-16 | Чувствительные данные и СМС-коды не записываются в технические логи в открытом виде | Дополнительно. Защита от утечек через логи |
| F-17 | В MVP клиент может подать заявку на накопительный счёт в интернет-банке. Заявку обрабатывает бэк-офис | Цели бизнеса |
| U | Удобство использования (Usability) | |
| U-01 | Интерфейсы соответствуют дизайн-системе банка: цвета, брендированные элементы и единые правила взаимодействия | Д5 |
| U-02 | Шаги подачи заявки, подтверждение и результат понятны клиенту, в том числе пожилому | Д5, основная аудитория банка |
| R | Надёжность (Reliability) | |
| R-01 | Сервисы работают 24/7 с доступностью не ниже 99,9%, включая интернет-банк | Д6. Для депозитного и кредитного направлений |
| R-02 | При отказе ЦОД интернет-банк остаётся доступным и выдерживает нагрузку | Д6. Резервный ЦОД уже есть |
| R-03 | Принятые заявки сохраняются при сбоях обработки и отказе одного рабочего ЦОД. После восстановления обработка продолжается | Дополнительно. При последовательной потере обоих рабочих ЦОД до восстановления репликации возможна потеря данных, принятых в аварийном режиме. Границы гарантии и порядок восстановления — в [Task3](../Task3/adr.md#размещение-и-резервирование) |
| R-04 | Повтор одного запроса или сообщения не создаёт дубли заявок и финансовых операций | Дополнительно. Защита от повторов при тайм-аутах и сбоях связи |
| R-05 | При недоступности АБС приём заявок продолжается. Заявки сохраняются и передаются на обработку после восстановления АБС | Уточнение Д6. Подтверждается приём, а не открытие продукта. Проверки и СМС-подтверждение сохраняются |
| P | Производительность (Performance) | |
| P-01 | Отклик сайта и интернет-банка, включая загрузку справочных данных, - меньше секунды | Д5. Время отклика, а не срок обработки заявки |
| P-02 | Решение по кредиту принимается в течение дня, если данных достаточно. Заявка по предодобренному предложению обрабатывается в тот же рабочий день | Цели бизнеса, К4 |
| P-03 | Новые заявки, включая накопленные за время сбоя, не перегружают АБС и не мешают основным операциям банка | Д6. База АБС уже перегружена |
| P-04 | Предрасчёт кредитных предложений не создаёт дополнительной нагрузки на рабочий скоринг в часы высокой загрузки | К5. Приоритет - обработка заявок |
| P-05 | Онлайн-сервисы масштабируются горизонтально. Запросы равномерно распределяются между серверами, приложениями и ЦОД | Д6, К4. Ограничение АБС - в +R-04 |
| S | Поддерживаемость (Supportability) | |
| S-01 | Компоненты и интеграции документированы для сопровождения и расширения системы | Д3 |
| S-02 | Решение опирается на компетенции команды банка | Д3. Предпочтительны знакомые языки и технологии |
| +R | Ограничения (Restrictions) | |
| +R-01 | Срок депозитного MVP - шесть месяцев. Обработка заявок остаётся за бэк-офисом | Цели бизнеса, Д4 |
| +R-02 | Доработки интернет-банка выполняет команда банка, по возможности без изменения ядра подрядчиком | Д2. СМС-функциональность находится в ядре |
| +R-03 | При необходимости брокера предпочтительна Kafka. Текущая платформа интернет-банка с ней несовместима | Д3. Микросервисы допустимы в рамках депозитного функционала |
| +R-04 | В новом процессе следует избегать прямых вызовов API АБС из интернет-банка. АБС масштабируется только вертикально | Д6. Ограничение перегруженной базы |
| +R-05 | Существующий обмен между БД АБС и Кредитного конвейера выполняется раз в сутки. Увеличить частоту нельзя | К4. Не обеспечивает обработку в тот же рабочий день |
| +R-06 | Внутренние данные для скоринга обновляются раз в сутки. БКИ вызывается онлайн через REST API | Исходный кредитный процесс, п. 3. Ограничение свежести данных |
| +R-07 | Приоритет - существующие технологии банка. Новые компоненты должны быть совместимы с действующими системами | Д3, IT-ландшафт. Интернет-банк: ASP.NET MVC 4.5/.NET Framework 4.5, MS SQL; АБС: Delphi, PL-SQL, Oracle; конвейер: Camunda, Java, Oracle; скоринг: Python, Flask, PostgreSQL; сайт: PHP, React; колл-центр: React, Spring Boot, PostgreSQL |
| +R-08 | СМС доставляются через банковский шлюз и внешнего телеком-оператора | IT-ландшафт. Внешняя зависимость подтверждений и уведомлений |
| +R-09 | Новый клиент проходит очную идентификацию в отделении перед открытием депозита или выдачей кредита | Д1, К1 |
